# v-appydave — Local Source of Truth

The actual recording data behind every FliLaunch project. FliHub serves this data as an API; v-appydave is the underlying filesystem. Direct read is faster for batch ops; FliHub adds BI on top.

## Root path

```
~/dev/video-projects/v-appydave/
```

## Project naming convention

Each project folder name is `<short-code>-<slug>`:
- `b65-guy-monroe-marketing-plan` — short code `b65`, slug `guy-monroe-marketing-plan`
- `c27-angeleye` — short code `c27`, slug `angeleye`
- Codes go `b65, b66, ..., b99, c01, c02, ..., c37, ...`
- `archived/` subfolder holds projects no longer in active rotation

## Per-project layout

```
~/dev/video-projects/v-appydave/<code>/
├── recordings/                 raw video files (.mov, .mp4)
├── recording-transcripts/      .srt + .txt + .json transcripts
├── recording-shadows/          metadata shadow files (one per recording)
└── edit-1st/                   first-edit working directory (when editing started)
```

## The naming convention IS the BI

Files inside `recording-transcripts/` follow `<chapter>-<segment>-<label>.<ext>`:

Real example from `c27-angeleye`:
- `01-1-intro.srt`, `01-2-intro.srt` — chapter 1 ("intro"), 2 segments
- `02-1-examples.srt` … `02-4-examples.srt` — chapter 2 ("examples"), 4 segments
- `03-1-development.srt` … `03-21-development.srt` — chapter 3 ("development"), 21 segments

What this gives every workflow before any AI runs:
- **Chapter boundaries** — chapter number changes encode the boundary
- **Chapter labels** — set by hand at recording time; serve as candidate YouTube chapter titles
- **Kickoff segment** — the `-1-` segment of each chapter sets the chapter's narrative tone
- **Effort signal** — segment count per chapter is a proxy for content density (1-segment = brief; 21-segment = deep)
- **Concatenable transcripts** — chapter-level transcript = `<chapter>-*-*.srt` joined in order

## Quick recipes

```bash
# Count active projects
ls ~/dev/video-projects/v-appydave/ | grep -v archived | wc -l

# List all recording-transcripts for a project
ls ~/dev/video-projects/v-appydave/c27-angeleye/recording-transcripts/

# Get chapter count for a project (count distinct chapter prefixes)
ls ~/dev/video-projects/v-appydave/c27-angeleye/recording-transcripts/*.srt | sed 's|.*/\([0-9]*\)-.*|\1|' | sort -u | wc -l

# Find all projects with no transcripts
for d in ~/dev/video-projects/v-appydave/*/; do
  [ "$(ls -A "$d/recording-transcripts/" 2>/dev/null | wc -l)" = "0" ] && echo "$d"
done
```
