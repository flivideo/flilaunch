Filter:
Sub-Delamains do not exist
Concept
Scaffolded a 'chapters' Delamain as a sub-flow of the main 'launch' Delamain — ALS has no such concept.
Rule
A Delamain is triggered by a delamain-typed field on an entity. No parent-child relationships. One entity + one concern = one Delamain with inlined states.
Corrected
Spec HITL gates ≠ Delamain operator gates
Concept
Translated all 7 spec UI touchpoints into Delamain operator gates — only genuine human decisions need gates.
Rule
Ask: "Can an agent make this decision reliably?" If yes, no gate needed. Agent-to-agent handoffs require no operator state.
Corrected
authoring.ts path must be absolute
Concept
Copied a relative path from the ALS reference system that only works inside the ALS monorepo.
Rule
Standalone projects must use the absolute installed path: /Users/<user>/.claude/plugins/cache/als-marketplace/als/<version>/alsc/compiler/src/authoring/index.ts
Corrected
Title source fields must be non-null
Concept
Used a nullable field (internal_label) in the entity title template — compiler error PAL-CV-SHAPE-001.
Rule
Any field in a document title source must have allow_null: false. Put optional fields in the body, not the title.
Corrected
provider required on all agent states
Concept
Left out 'provider: anthropic' on every agent state — compiler caught all of them.
Rule
Every state with actor: agent must declare provider. Valid values: 'anthropic', 'openai'. There is no default.
Corrected
session-field required on resumable states
Concept
Marked states resumable: true without providing the session-field name for recovery.
Rule
resumable: true requires session-field: '<name>'. Implicitly added to entity frontmatter at runtime — no need to declare in entity fields block.
Corrected
System root is project root, not .als
Concept
Passed .als as the system root — compiler looked for .als/.als/system.ts (double path error).
Rule
The system-root argument is . (project root). The compiler appends .als/system.ts itself. Always run from project root.
Corrected
Compiler is source of truth, not skills
Concept
/als:init and the compiler are known to be unaligned in 0.1.0-beta.28.
Rule
If alsc validate passes, the scaffold is correct regardless of what /als:init generates. Use the compiler as the arbiter.
Known
Dispatcher is commit-driven, not CLI-driven
Concept
Expected a command to advance a Delamain step-by-step — the dispatcher polls git HEAD for committed state changes.
Rule
Commit a state change → dispatcher sees it on next poll (30s) → invokes the agent → auto-commits result. No manual trigger.
Corrected
Deploy and bootup are separate operations
Concept
Assumed running bootup would also compile and deploy the module — they are two distinct steps.
Rule
alsc deploy claude . projects .als/ to .claude/. /als:bootup starts dispatchers. Neither does both. No skill exists for deploy (filed: nfrith/als#2).
Corrected
Hook-centric fan-out
Decision
Nick's diagram had thumbnail deriving from title — we made both title and thumbnail derive from hook.
Rationale
Hook is the framing angle. Both title (text) and thumbnail (visual) express the same hook independently. Deriving thumbnail from title creates redundancy and weaker CTR.
Accepted
4 operator gates (not 7, not 3)
Decision
Iterated from 7 spec gates → 3 (too few, missed chapters) → 4 (correct final count).
Rationale
Gates: awaiting-input, awaiting-hook-selection, awaiting-chapter-review, awaiting-review. All other transitions are agent-to-agent.
Accepted
Chapters inlined into launch Delamain
Decision
Originally a separate chapters Delamain — dropped and inlined as 3 states after Nick pointed out it was orphaned.
Rationale
One entity + chapter processing as part of main flow = inline. Use a second Delamain field only if the concern is genuinely parallel and independent.
Accepted
Analysis = 12 parallel prompts, no gate
Decision
Ran 12 parallel sub-agent prompts for analysis — purely extractive, no human judgment needed.
Rationale
Analysis feeds hook generation. All 12 results land in ANALYSIS section. Made resumable because 12 parallel agents is long-running.
Accepted
Chapter timing = tool call, not workflow state
Decision
Timing adjustment is mechanical (index + arithmetic) — doesn't need AI reasoning or a Delamain state.
Rationale
The Delamain models decisions, not tools. External fine-tuning tool runs out-of-band during awaiting-chapter-review gate.
Accepted
internal_label excluded from title template
Decision
internal_label is optional annotation — excluded from title template because compiler requires non-null title sources.
Rationale
Title source = project_code only. Always non-null, always unique. internal_label stays in entity body as optional metadata.
Accepted
Module named fli-launch
Decision
AWB already has youtube-launch-optimizer — used fli-launch to namespace to FliLaunch and avoid collision.
Rationale
Namespace modules to the product they belong to. Skill IDs become fli-launch-manage and fli-launch-pipeline — unambiguous.
Accepted
Two skills: manage + pipeline
Decision
Split into fli-launch-manage (CRUD) and fli-launch-pipeline (operator console) — separate administration from operation.
Rationale
Manage = session lifecycle. Pipeline = workflow operation. Follows ALS reference system conventions, avoids a bloated skill.
Accepted
FliHub as transcript source
Decision
Agent calls FliHub API with project_code rather than reading filesystem paths directly.
Rationale
FliHub is the canonical video project management system. It normalizes data. Agents shouldn't need filesystem knowledge.
Accepted
No /als:deploy skill
Gap
After authoring a module, there is no skill to project .als/ to .claude/ — must run the compiler command manually.
Workaround
Filed as nfrith/als#2. Run: bun /path/alsc/compiler/src/cli.ts deploy claude .
Filed #2
/als:init and compiler not aligned
Gap
/als:init generates a different scaffold shape than what the compiler validates as correct.
Workaround
Known pre-release gap, confirmed by Nick. Use compiler as source of truth. Scaffold manually if /als:init output fails validation.
Known
Sub-Delamain concept underdocumented
Gap
Operators from nested workflow systems expect child workflows — ALS has no such concept, but it's not prominently documented.
Fix needed
Should add to ALS docs: "No sub-Delamain concept. Inline states or add a second delamain-typed field on the entity."
Known
Compiler error output is JSON, not human-readable
Gap
Running alsc validate directly produces structured JSON with error codes — requires parsing to understand.
Workaround
Use /als:validate skill which interprets errors in readable form, or pipe to jq.
Known
No session seeding skill or template
Gap
Creating the first entity record requires the module's manage skill — no generic scaffold or template generator.
Workaround
Use /fli-launch-manage → Create. The manage skill handles record creation with correct frontmatter.
Known
authoring.ts absolute path not documented
Gap
Reference system examples use a monorepo-relative path that fails in standalone projects — not documented anywhere.
Fix needed
ALS install docs should note standalone projects need the absolute installed path in authoring.ts.
