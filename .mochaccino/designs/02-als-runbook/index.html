ALS Operator Runbook

From scaffold to running Delamain — the complete 6-phase path

Purpose
The ordered path from an empty project to a running ALS Delamain. Six phases, in sequence, each with its checks and the trap waiting for you if you skip ahead.
Audience
David — walk it top to bottom when starting any new module. Nick — see which phase loses operators and where the gates need stronger language.
How to read
Top phase first. Each layer is one phase: what you do, what to check before advancing, and the ⚠ gotchas that bit you the first time around. Don't jump phases.
Takeaway
Use this as the spine of any new ALS module build — including today's workflow design with Nick.
1
Author
Write .als/ files — delamain.ts, module.ts, agents, skills
Validate command
bun /Users/davidcruwys/.claude/plugins/cache/als-marketplace/als/0.1.0-beta.28/alsc/compiler/src/cli.ts validate .
Produces
.als/ directory — authoring.ts, system.ts, module.ts, delamain.ts, agent .md files, skill SKILL.md files. Must return "status": "pass" before proceeding.
authoring.ts must use absolute installed path — not monorepo-relative
Nullable fields in title template → PAL-CV-SHAPE-001 compiler error
All agent states need provider: anthropic
Resumable states need session-field declared
2
Deploy
Project .als/ to .claude/ — skills, delamain, dispatcher
No skill yet — manual
Command (run manually)
bun /Users/davidcruwys/.claude/plugins/cache/als-marketplace/als/0.1.0-beta.28/alsc/compiler/src/cli.ts deploy claude .
Produces
.claude/skills/<id>/SKILL.md · .claude/delamains/<name>/delamain.yaml · .claude/delamains/<name>/dispatcher/ · .claude/delamains/<name>/runtime-manifest.json · .als/CLAUDE.md
No /als:deploy skill exists — filed as nfrith/als#2. Run manually every time .als/ changes.
Pass . as system root, not .als — otherwise double-path error
Claude Code Desktop requires session restart to discover newly deployed skills
3
Install Dispatcher Deps
One-time per first deploy — node_modules preserved after that
Command
cd .claude/delamains/launch/dispatcher && bun install
Produces
.claude/delamains/launch/dispatcher/node_modules/ — 101 packages. Takes ~64 seconds on first run. Preserved on subsequent deploys.
Must run before bootup — dispatcher won't start without dependencies
4
Bootup
Start dispatcher(s) — repeat at start of every Claude Code session
Command
/als:bootup
Produces
Running dispatcher processes polling git HEAD every 30s. Delamain dashboard at http://127.0.0.1:4646. Agent states run automatically from this point.
Dispatchers die when the Claude Code session ends — re-run /als:bootup each new session
Use /als:reboot to restart only crashed dispatchers without killing running ones
5
Create Session
Provision a new entity record — the unit of work the Delamain operates on
Command
/fli-launch-manage
→ Select "Create" → provide project_code
Produces
fli-launch/sessions/<id>.md — entity record with status: awaiting-input. Dispatcher is aware but will not act — awaiting-input is operator-owned.
Entity file must be committed to git — dispatcher only reads committed HEAD
6
Operate
Act at human gates — dispatcher handles agent states automatically between them
Command
/fli-launch-pipeline
4 Operator Gates
Gate 1awaiting-input — provide project_code, optional focal point Gate 2awaiting-hook-selection — select 1–3 hook angles (drives titles + thumbnails) Gate 3awaiting-chapter-review — review/refine chapter labels, external fine-tune here Gate 4awaiting-review — final selections: titles, thumbnail, description, tags
Dispatcher must be running (bootup) for agent states to execute automatically
Can rework: hook-selection → regenerate-hooks · review → hook-selection
